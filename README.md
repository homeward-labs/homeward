# 家卫 Homeward

> 一个可自建的**轻量服务** —— 跑在你自己掌控的那台设备上（软路由 / NAS / 旧电脑 / 任意 Linux），**看清家里每个联网设备（智能硬件 / 手机 / 电脑）在跟谁说话**；（一键拦下可疑外联为**标准版**能力，版本与功能边界见私有《版本与能力归属》文档）。

**家卫是「设备外联流量治理」工具，不是摄像头、不是安防监控 App。** 我们不拍你、不装你的设备，只在网络层**看清**谁在给外面打电话；真正**拦下**外联是标准版能力。

- 中文文档：[docs/README.md](docs/README.md) · **部署形态：[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)** · 阻断策略与竞品分析：见私有《阻断与撤销》《竞品分析》文档（不随本仓库发布）
- **开源边界（社区版开源 / 标准版·专业版闭源）**：见私有《版本与能力归属》文档

## 它能做什么

| 维度                 | 能力                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **看见**             | 自动发现家里的联网设备（摄像头/电视/音箱/扫地机/门铃…），画出每个设备连了哪些外部域名与组织；识别突发上传、心跳信标、半夜异动、局域网内跨设备追踪；**把加密 DNS 等看不到的盲区在 UI 上明示**。                                                          |
| **拦下（标准版 · 闭源付费）** | 三级阻断：软（DNS 级 NXDOMAIN）/ 中（网段·ASN 级 drop）/ 硬（VLAN 隔离）。阻断前预览后果；**30 分钟内一键撤销，且永远可人工恢复**；撤销后主动核验设备真的恢复。<br>⚠️ 阻断执行属于**标准版**（闭源、付费）；社区版（开源免费）仅能「建议阻断」并预览后果，**不能实际拦截**。 |
| **读懂**             | 中文人话告警（"客厅摄像头半夜向陌生 ASN 连了 73 次"）；判定可解释；AI 辅助默认关闭、需手动触发。                                                                                                           |

**与"只看不拦"类工具的根本区别**：标准版能真的把可疑外联拦下来（社区版仅展示建议），并把"拦得住/拦不住、看得到/看不到"都诚实写给你。

---

## 它不做什么（边界）

- 不解密 TLS（纯元数据判断，合法、可落地、低功耗可跑）
- 不做杀毒、不做企业级 DLP
- 不是摄像头/安防监控 App，不采集你的音视频
- 不默认自动阻断，一切以你确认为准

## 部署：跑在你自己掌控的那台设备上

**家卫是一个服务，不是一个绑定平台的 App。** Docker 只是安装方式之一，飞牛只是目标平台之一 —— 两者都不是定义。它也能原生跑在软路由、旧电脑或任意一台 Linux 上。

| 你想装在哪               | 推荐方式                        | 能看到多少                       |
| ------------------- | ------------------------- | -------------------------- |
| **软路由 / iStoreOS（主力） / OpenWrt** | 原生安装（网关位，能力最完整）             | 全量流量（iStoreOS 自带 Docker，今天即可用 Docker 形态坐网关位；原生商店包为最高优先级）          |
| **双网口 NAS / 旧电脑**（可串在网络里） | Docker（网桥串联）               | 全量流量                       |
| **单网口 NAS**（飞牛 / 群晖 / 威联通） | Docker（单臂旁听）               | ⚠️ 仅 DNS 层                 |
| **任意 Linux 主机 / 物理机**  | Docker 或原生 systemd（原生为计划中） | 取决于接入方式                    |

完整对照（接入方式 / 运行平台 / 安装方式三个维度）见 **[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**。

```bash
# Docker（当前唯一可实际跑起来的方式）
git clone https://github.com/homeward-labs/homeward
cd homeward
docker compose up -d
# 打开 http://<设备IP>:9595
```

**其他平台的原生包（`.fpk` / `.ipk` / systemd 单元）目前都是「计划中、未实现」** —— 例如 `fnpk/` 仅含飞牛打包配置草稿，尚未提交审核、也未上架应用中心。在这些产物落地前，请使用上面的 Docker 方式，或直接跑：

```bash
# 界面自测（灌入演示数据，端口 9595）
python -m src.ui.server --demo
# 只跑核心服务演示（命令行输出，不起界面）
python -m src.core.main
```

> 当前版本 **没有鉴权**：把 9595 暴露到不受信任的网络前请先加反代或防火墙限制，
> 非回环地址启动时会打印告警。采集层接真机数据源是 W5 的工作，
> 现在界面上的数据来自演示剧本（`--demo`）。

> 单网口 Docker 形态下只能看到 DNS 层面（设备往哪个域名打电话）；要看全量流量，请部署为网关位（主路由 / 旁路由）或双网口网桥。
