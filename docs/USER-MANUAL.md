# 家卫（Homeward）使用手册 · iStoreOS 版

> 这份手册是给**在家里用 iStoreOS 软路由、装了家卫的普通用户**看的。
> 只讲怎么装、怎么用，不涉及技术原理和内部实现。

## 一、家卫能帮你做什么

家卫会**记录家里每一台联网设备都在跟谁联网**，并**提醒你哪些连接可能有隐私风险**。

- 手机、电视、摄像头、音箱……连了哪些外面的服务器，家卫都帮你记下来；
- 发现可疑的（比如某台设备半夜偷偷往外传数据），家卫会**提醒你**；
- 标准版还能在提醒的基础上，**直接拦住**这些连接。

**家卫不联网也能正常工作**——它在本机记录和分析，断网也能用、也会继续记录。
只有下面两件事需要联网：

1. **日常升级**（修问题、加功能）；
2. **拉取特征库**（用来判断「某个网址属于哪家公司」的更新数据）。

> 你家的所有联网记录都只存在你自己的路由器上，不会传到外面去。

## 二、在 iStoreOS 上安装家卫

### 自动安装（推荐，最简单）

> ⚠️ iStoreOS 默认**没有 `git`**，所以不用 git。下面这条命令**很短、没有任何引号**，
> 复制粘贴到任何终端都不会出错（之前长命令里的引号会被网页终端转成全角，导致 shell 一直等待、看似卡死）。

在 iStoreOS 终端（SSH）里执行这一条命令，回车后等着看一步步打钩就行：

```bash
wget -qO- https://ghfast.top/https://raw.githubusercontent.com/homeward-labs/homeward/main/scripts/boot-istoreos.sh | sh
```

这条命令只做一件事：从 GitHub 拉取几行的引导脚本并运行。引导脚本会**自动**：
1. 下载家卫源码包（带进度条，直连慢自动换国内镜像）；
2. 校验并解压；
3. 启动正式安装——内部**自动分 5 步、每步打完 ✓ 再进下一步**，失败就停在那一步并告诉你原因和怎么办。

**你会看到的界面**：

```
===== 第 1 步 / 共 5 步：检查路由器网络 =====
  ✓ 外网连通（ping 223.5.5.5 正常）
  ✓ DNS 解析正常

===== 第 2 步 / 共 5 步：下载家卫源码包 =====
  尝试下载源：https://ghfast.top/https://github.com/...
  ✓ 下载完成

===== 第 3 步 / 共 5 步：校验并解压 =====
  ✓ 压缩包完好
  ✓ 解压完成

===== 第 4 步 / 共 5 步：让路由器开始记录 DNS 查询 =====
  ✓ dnsmasq 已配置并重启（日志写入 /tmp/dnsmasq.log）
  ✓ 日志文件已生成

===== 第 5 步 / 共 5 步：拉起家卫容器 =====
  （首次构建镜像约 3~10 分钟，输出滚动属正常，请不要关闭窗口）
  ✓ 家卫容器已启动

======================================
 ✓ 全部 5 步完成！
   浏览器打开：  http://192.168.x.x:9595
======================================
```

> **重跑很安全**：哪步失败就修那步说的事，然后重新执行上面那条一键命令——已下载好的包会自动跳过下载。
> 路由器重启后无需重装：DNS 日志配置已永久保存，容器设置开机自启即可。

### 装完后：面板为什么是空的？——让设备连进来

安装完成后打开面板，**大概率是空的**：这不是要等，而是还没有任何设备把域名查询发到这台路由器。要让设备「经过」它，有两条路：

**方式一：给这台软路由开 WiFi（推荐，前提是它自带无线网卡）**

有两种用法：

| 用法 | 怎么做 | 适合 |
|------|--------|------|
| **当主路由** | 家里宽带直接接到它，设备连它的 WiFi 上网 | 想让它全面接管网络 |
| **当旁路由** | 主路由不动，只把想管的设备的**网关和 DNS** 改成这台软路由的 IP | 想先试用、不影响现有网络 |

> 💡 **建议把它的 WiFi 名设成和主路由不一样**（比如主路由叫 `Home`，这个叫 `Home-IoT`）：
> 智能设备连 `Home-IoT`、手机电脑连主路由，**分成两个网络**——
> ① 好管理：智能设备的联网一目了然；② 更安全：智能设备和私人设备互相隔离；
> ③ 这台软路由万一坏了或重启，手机电脑照常上网，**不影响家里正常网络**（旁路由最大的好处）。

> 透明网桥等其他接法：后续版本计划支持。

**方式二：手动指定个别设备的 DNS**

有些智能设备不支持换网络，或你想单独盯住某一个：把**那台设备的 DNS 服务器**手动改成这台软路由的 IP（如 `192.168.1.1`）即可，它的联网记录就会出现在面板里。

> 想主动「盯住」某个设备的更多办法（一键接管某设备全部流量等），将在后续版本提供。

**安全提示**：面板默认只建议在内网访问。确需暴露到公网，先在 `docker/.env` 里设置 `HOMEWARD_AUTH_TOKEN`（访问口令，用 `openssl rand -hex 16` 生成），再重启容器。

### 手动安装（想自己掌控每一步时用）

**第 1 步：让路由器开始记录 DNS 查询（一次性）**

家卫的数据来源是路由器的 DNS 查询记录。先让 iStoreOS 把它记到文件：

- 图形界面：iStoreOS 管理页 → **网络** → **DHCP/DNS** → 点开「**日志**」标签页（不在「常规」里）→
  ① 勾选「**记录 DNS 查询**」；
  ② 在「**日志设施**」下拉框里选 `/tmp/dnsmasq.log`。
  > ⚠️ **第一次**列表里通常没有 `/tmp/dnsmasq.log`：要在下拉框**最下面的输入框里手动输入
  > `/tmp/dnsmasq.log`，按回车**把它加进列表，再选中它，然后保存并应用。
  > 不同版本界面略有差异：若「日志」页找不到该输入框，跳过图形界面，用下面的终端命令即可。
- 终端（SSH）：
  ```bash
  uci set dhcp.@dnsmasq[0].logqueries='1'
  uci set dhcp.@dnsmasq[0].logfacility='/tmp/dnsmasq.log'
  uci commit dhcp
  /etc/init.d/dnsmasq restart
  ```
- 验证：`cat /tmp/dnsmasq.log` 能看到 `query[A] example.com from 192.168.x.x` 这样的行，说明成功。

> **补充**：`/tmp` 是内存临时区，路由器重启后日志文件会清空（但上面的配置已永久保存，重启后系统会自动重建空文件、继续记录）。这只影响历史查询记录，不影响正常使用。

**第 2 步：拉起家卫**

> iStoreOS 默认没有 `git`，下面用「下载源码压缩包 + 解压」的方式（不需要 git）：

```bash
cd /tmp
U=https://github.com/homeward-labs/homeward/archive/refs/heads/main.tar.gz
curl -fL --connect-timeout 15 --progress-bar -o hw.tar.gz "$U" \
  || curl -fL --connect-timeout 15 --progress-bar -o hw.tar.gz "https://ghfast.top/$U" \
  || wget -O hw.tar.gz "https://ghfast.top/$U"
tar xzf hw.tar.gz
cd homeward-main
docker compose -f docker/docker-compose.istoreos.yml up -d
```

浏览器打开 `http://<你的路由器IP>:9595` 即可。

**第 3 步（可选）：暴露到公网时设口令**

默认只有你家局域网内的人能打开。若要把 9595 端口暴露到公网，务必设登录口令：

```bash
cp docker/.env.example docker/.env
# 编辑 docker/.env，把 HOMEWARD_AUTH_TOKEN= 填上：openssl rand -hex 16
docker compose -f docker/docker-compose.istoreos.yml up -d
```

## 三、第一次打开：让面板有数据

刚装好时面板**可能是空的**——这不是坏了：家卫要等家里设备开始上网、产生查询后，才会逐渐出现数据。

- 一般**几分钟内**就会有设备、域名冒出来；
- 如果等了一阵还是空的：打开「**盲区**」视图，看 DNS 采集器是不是「可用」；若显示不可用，回到第二节确认 DNS 日志路径是否生效。

## 四、界面怎么看

打开 `http://<路由器IP>:9595` 后，顶部是一排标签页：

| 标签页 | 看什么 |
|---|---|
| **概览** | 家里设备总数、外联去向数、风险提醒数 |
| **设备** | 每台设备的 IP，以及它连过哪些外部服务器 |
| **去向** | 这些外部服务器分别属于哪些公司 / 组织 |
| **风险提醒** | 可疑的联网行为（如某设备深夜偷偷回传数据） |
| **建议** | 可以做的隐私加固动作 |
| **盲区** | 当前看不到的部分——家卫会诚实告诉你，不会假装全知 |
| **升级** | 免费版 → 标准版，解锁「直接拦住」能力 |

## 五、免费版与标准版

- **免费版**：帮你**记录和提醒**，已经能看清家里谁在跟谁说话；
- **标准版**：在免费版基础上，能**直接拦住**可疑连接（误拦可回退）。

如果你只需要「搞清楚家里联网情况」，免费版够用；想要「不仅看见、还能拦」，再在「升级」标签页激活标准版。

## 六、常见问题

**Q：面板一直空白？**
A：先看「盲区」视图，确认 DNS 采集器「可用」。最常见原因是没开 dnsmasq 日志（回到第二节第 1 步）。

**Q：为什么只看到连了哪些域名，看不到流量大小 / 时间线？**
A：这是当前部署形态（只读取 DNS 记录）的视野上限，不是故障。要看全量流量需要把家卫放到网关位置。家卫会在「盲区」里明确告诉你当前看不到什么。

**Q：打不开 9595？**
A：检查防火墙是否放行 9595；`docker ps` 看 homeward 是否在运行；确认访问的是路由器局域网 IP。

**Q：下载源码包时进度条不动 / 一直卡着？**
A：是 GitHub 直连慢，不是死机。命令会在约 15 秒内自动改走镜像加速；若镜像也下不动：① 换个时间段再试；② 用手机热点给路由器联网后重试；③ 或者在电脑浏览器里打开下载地址，手动把压缩包拷到路由器 `/tmp` 目录再解压。

**Q：去向里的域名很多显示「未识别」？**
A：正常现象。判断「域名属于哪家公司」靠内置的特征库，而特征库只收录了常见的家用设备与服务，覆盖不了的域名会如实标注「未识别」——家卫绝不瞎猜。对拿不准的域名可以在面板里手动发起深入分析。

**Q：面板出现「127.0.0.1」的设备？**
A：那是路由器本机自己的联网行为（应用商店、动态域名、系统服务在往外连），不是别人接入你家网络。面板会把它标成「路由器自身」。看见路由器自己在跟谁说话，恰恰是家卫的价值之一。

**Q：收到「疑似 DNS 隧道」告警，是真的吗？**
A：先别慌。家卫只在设备持续高频查询（整分钟每秒好几次）或出现超长随机子域时才告警。点开告警看它列出的证据（查了什么域名、多快）；确认是路由器自身或你认识的设备的正常批量解析，可以直接忽略该条。拿不准就发出来一起看。

**Q：断网了家卫还能用吗？**
A：能。家卫在本机记录和提醒，断网照常工作。只有「升级」和「拉取特征库」才需要联网。
