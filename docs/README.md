# 家卫 Homeward — 家庭联网设备隐私守护

> **一句话**：一个可自建的**轻量服务**（跑在你自己掌控的那台设备上：软路由 / NAS / 旧电脑 / 任意 Linux），**看清家里每个联网设备（智能硬件 / 手机 / 电脑）在跟谁说话，并在你决定动手之前把后果讲清楚**。
>
> **关于「拦下」**：真实阻断属于**标准版**（闭源付费）；社区版只提供「建议阻断 + 后果预览」。
> 标准版对每个拦截动作保留 **30 分钟一键撤销**窗口 —— 这是**撤销窗口**，不是规则寿命：
> 规则默认持久生效直到你显式撤销，两者互不推导，详见 [BLOCKING.md](./BLOCKING.md) 第四节。
> （早期文案写成「30 秒**内**一键拦下」，把这两个完全不同的时间语义混成了一句，已修正。）
>
> **品类锚定**：家卫是「**设备外联流量治理**」工具，**不是摄像头、不是安防监控 App**。我们不拍你、不装你的设备，只在网络层看清谁在给外面打电话；真正拦下外联是标准版能力。
>
> **版本与功能归属**：本文全量能力横跨社区版（开源免费·仅"看见"）与标准版（闭源付费·含"拦下"）。阻断执行仅标准版提供；社区版只展示"建议阻断"。详见 [EDITIONS.md](./EDITIONS.md)。

## 它为什么存在

家里的联网设备是家庭隐私最大的黑洞。它们：

- 不更新固件、不拒绝更新，自己也不会装任何安全工具；
- 硬编码 DNS（如 8.8.8.8），绕过普通 DNS 过滤；
- 在局域网内互相发现、互相追踪（UPnP / mDNS / SSDP）；
- 把数据发往用户完全不知道的第三方域名与组织。

**这个品类在家庭侧目前几乎是空白。** 企业有 DLP，路由器有防火墙，但没有一个产品能平白地告诉普通人：「你的摄像头正在把数据发给谁，以及你能不能让它闭嘴」。

## 你能用它做什么（核心功能）

### 一、看见 —— 把"看不见"变成"看得见"

| 能力 | 说明 |
|---|---|
| 设备发现 | 自动识别家里不能装软件的联网设备：摄像头、智能电视、音箱、扫地机、门铃、灯泡……（也能观察手机 / 电脑的外联） |
| 去向地图 | 每个设备连了哪些外部域名 / 组织，画出去向关系 |
| 域名 → 组织归属 | `api-edge.tuya.com` → 涂鸦智能；`data.mistat.xiaomi.com` → 小米遥测 |
| 行为识别 | 突发大流量上传、固定间隔心跳信标、半夜异常外联、局域网内跨设备追踪（UPnP/mDNS/SSDP） |
| **盲区明示** | 加密 DNS（DoH/DoT）、应用层流量等**看不到的地方，UI 上直接写出来**，绝不假装看得比实际多 |

### 二、拦下（⚠️ **标准版**能力 · 闭源付费） —— 看见之后，还能动手（这是与"只看不拦"类工具的根本区别；社区版仅展示"建议阻断"）

| 能力 | 说明 |
|---|---|
| 三级阻断 | 软（DNS 级 NXDOMAIN）/ 中（网段 · ASN 级 drop）/ 硬（VLAN 隔离，需交换机或 OpenWrt 配置权） |
| 阻断前后果预览 | 拦之前告诉你「摄像头云录像会失效，本地画面不受影响」，不做黑盒恐吓 |
| **30 分钟内一键撤销** | 每个拦截动作都有撤销窗口；窗口过后也永远提供人工恢复通道，**不存在"解不开"的死角** |
| **撤销后核验** | 撤销成功 ≠ 设备真的恢复了。系统会主动核验（dnsmasq 已重载 / nftables 句柄已删 / 端口已回原 VLAN），核验失败会显式报给你 |

### 三、读懂 —— 用中文人话，不当黑盒

| 能力 | 说明 |
|---|---|
| 中文人话告警 | 「客厅摄像头在半夜 2 点，向一个从没联系过的 ASN 连了 73 次」 |
| 判定可解释 | 每条告警都说明"做了什么 + 为什么判定"，不吓人不隐瞒 |
| AI 辅助（默认关闭） | 未知域名分析、人话翻译；需你手动触发，绝不默认联网分析 |

## 它**不**做什么（Non-goals）

为避免误解（尤其是"家卫"二字容易联想到摄像头安防 App），明确边界：

- **不解密 TLS**：纯靠元数据（目的地、频率、时序、包大小、SNI）判断，合法、可落地、能在低功耗设备上跑；
- **不做杀毒、不做企业级 DLP**；
- **不是摄像头 / 安防监控 App**：我们管"设备外联去向"，不采集你的音视频；
- **不默认自动阻断**：一切以你确认为准（除非你自己设定了自动规则）；"软阻断广告追踪"这类低风险动作才允许预设。

## 架构：采集与执行正交

「采集（怎么看）」与「执行（怎么拦）」是两个**正交维度**，组合成一张 2×4 网格，而非一条"档位 A/B"的轴。关键不变量：**硬阻断（VLAN 隔离）依赖交换机 / OpenWrt 配置权，与采集方式无关**。上层（前端 / 决策引擎）只问 `Capabilities`，不绑定具体平台。

```
                       ┌─────────────────────────────┐
                       │   Web UI / 手机端            │
                       │   (中文人话告警 + 一键操作)   │
                       └──────────────┬──────────────┘
                                      │
                       ┌──────────────┴──────────────┐
                       │   核心服务 (core/)           │
                       │  ┌────────────────────────┐  │
                       │  │ 规则匹配引擎            │  │
                       │  │ · 域名→组织归属          │  │
                       │  │ · 行为特征签名           │  │
                       │  │ · 固件漏洞库             │  │
                       │  │ · 判定与建议生成         │  │
                       │  └────────────────────────┘  │
                       │  ┌────────────────────────┐  │
                       │  │ 知识库                  │  │
                       │  │ · 域名归属 (众包可贡献)  │  │
                       │  │ · ASN/注册机构          │  │
                       │  │ · 行为模式库            │  │
                       │  └────────────────────────┘  │
                       │  ┌────────────────────────┐  │
                       │  │ AI 辅助层 (默认关闭)    │  │
                       │  └────────────────────────┘  │
                       └──────────────┬──────────────┘
                                      │
                       ┌──────────────┴──────────────┐
                       │   适配器层 (adapters/)        │
                       │   Collector（只看）          │
                       │   Enforcer（只拦）          │
                       │   二者经 Capabilities 协商    │
                       └──────────────────────────────┘
```

## 部署形态（决定你能看到多少）

**家卫不绑定任何平台。** 决定能力上限的是「流量怎么到它手上」，而不是它跑在什么牌子的机器上。

| 接入方式 | 典型设备 / 拓扑 | 能看见 | 盲区 |
|---|---|---|---|
| **网关位**（推荐） | 软路由主路由 / 旁路由（OpenWrt · iStoreOS · x86） | 全量：DNS + 连接五元组 + 流量大小与时序 | 加密 DNS 内容、TLS 内层 |
| **网桥串联** | 双网口 NAS / 双网口 x86 / 旧电脑加网卡 | 全量（libpcap 旁路） | 同上 |
| **单臂旁听** | 单网口 NAS（飞牛 / 群晖 / 威联通）、普通 Linux 主机 | ⚠️ **仅 DNS 层**：哪个设备问了哪个域名 | 不走本地 DNS 的连接、硬编码 DoH、**流量大小与时序全盲** |
| **只读日志** | 开发机，不接入网络 | 取决于喂进去什么 | 大 |

**安装方式**与上面正交：Docker Compose（✅ 当前唯一可跑）· 源码直跑（✅ 开发用）· 原生 systemd / OpenWrt 包 / 飞牛 `.fpk`（⬜ 均计划中、未产出）。

完整三维度对照见 **[DEPLOYMENT.md](./DEPLOYMENT.md)**。

## 三级阻断与撤销语义（摘要）

详见 [BLOCKING.md](./BLOCKING.md)。对外只说一句话：**每个拦截动作，30 分钟内可一键撤销**。

关键不变式：

- `redeemable_until` 管「撤销按钮还在不在」；`auto_release_at` 管「规则还生不生效」，默认 `None`（持久生效直到你显式撤销）。
- **窗口过期 ≠ 规则解除**，也**≠ 解不开**：过期只是按钮消失，规则照旧生效，且永远可用人工通道恢复。
- **撤销成功 ≠ 已恢复**：必须跑 `verify_revert()` 核验设备真的恢复了，不允许静默。
