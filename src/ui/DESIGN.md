# 家卫 Web UI · 设计系统（DESIGN）

> **定位**：本文件是家卫 Web UI（`src/ui/`）**视觉设计的唯一真相源**。
> **冻结**：`src/ui/static/app.css` 的 `:root` 令牌表以本文件为准 —— 令牌的**名字与语义**不得随意更改；
> 新增颜色 / 圆角 / 阴影 / 字体的唯一合法路径是**先在本文件登记，再写进 `app.css` 的 `:root`**，
> 之后视图代码一律用 `var(--…)` 引用。**禁止在视图里写死色值**（现存违规见 §4）。
>
> **版本**：v1.0（2026-10-30 立）｜**维护**：见 §6 变更规则｜**落地状态**：令牌表已存在（`app.css:6-61`），迁移进行中

## 0. 一句话

Apple 风（浅色 · 毛玻璃 · 大圆角）：macOS / iOS 原生观感 —— 半透明毛玻璃导航、大圆角卡片、
系统字体栈、柔和分层阴影、克制的蓝色强调 + 绿 / 橙 / 红语义色。
**零外部资源**：不引 CDN、不引网络字体、不引图标库；图标一律**内联 SVG**（禁用 emoji）。

## 1. 设计原则（四条）

| # | 原则 | 落地要求 |
|---|---|---|
| 1 | **令牌唯一** | 所有颜色 / 圆角 / 阴影 / 字体只从 `:root` 取；视图里出现裸值即技术债（§4） |
| 2 | **零外部请求** | 不引任何第三方 CSS / 字体 / 图标 / JS 库；这是一个隐私产品的卖点，不是省事 |
| 3 | **语义优先** | 用 `--danger` 而不是「那个红色」；用 `--sev-critical` 而不是字面色号 |
| 4 | **克制** | 强调色只有蓝一种；绿 / 橙 / 红只承担语义，不做装饰 |

> **技术选型约束（硬）**：**不引入** React / Vue / Svelte / TypeScript / 打包器（webpack / vite）。
> 理由：零第三方依赖是社区版承诺（`requirements.txt` 为空、页面零外部资源），
> 且当前 11 个视图的规模远未到需要框架的临界点；组件复用靠**人工纪律 + 本文件**保证。
> 如果将来视图数或状态复杂度真的越界，需要**单独出 ADR 讨论**，不得顺手引入。

## 3. 使用规则

1. **取色只走 `var()`**：`background: var(--surface)` ✅；`background: #ffffff` ❌。
2. **行内样式可用令牌**：JS 内联样式写 `style="color:var(--danger)"` 是允许且推荐的（见 `app.js` 现有写法）。
3. **JS 中的分类色必须集中**：图表 / 标签的调色板**只允许**定义在 `app.js` 的 `catColors` 一处（当前实现），
   不要在渲染函数内部另起字面量。
4. **新增令牌判定**：先问「这是不是已有语义的另一档？」——是就复用；不是才新增，并同时在 §2 登记。
5. **命名约定**：语义令牌用「名词 / 状态」（`--danger`、`--sev-high`），**不要**用色相命名（`--red`、`--blue`）。

## 6. 变更规则

1. **改令牌值**：本文件 §2 与 `app.css:6-61` **必须同一次改动内同步**，否则本文件立即失效。
2. **加令牌**：先加 §2 表行（写清值 + 用途），再写 `app.css`。
3. **删令牌**：先确认全库无引用（`grep -rn "var(--<名>" src/ui/static/`），再从两处同时删除。
4. **改公共布局**：按 §5 回归清单逐视图目视核对（浅色 / 深色登录页 / 窄屏三档）。
5. **提交前自检**：
   ```bash
   # 视图里不应出现裸色值（:root 与允许的旧名区之外）
   grep -nE '#[0-9a-fA-F]{3,8}\b' src/ui/static/app.js src/ui/static/charts.js
   ```
   输出应逐步收敛到 §4 表格中的已知条目。
